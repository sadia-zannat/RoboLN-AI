# Manual acceptance tests — desktop and mobile

Run these in a disposable local project on desktop, tablet 768px and mobile 390px/320px widths. The release environment could not execute browser assertions. Record actual results and failures; these steps are not pre-marked PASS.

1. Register, sign out, sign in and create two projects. Confirm project navigation, breadcrumbs, Back/Forward and refresh. Open Build Copilot from the sidebar and the original Live Build entry card.
2. Add equipment with two photographs, quantities, unknown specifications and a datasheet reference. Correct the name/model and BOM association. Verify the missing-parts list changes. Confirm another project cannot retrieve its photo URL.
3. Generate a project-template plan without a key. Start, enter check notes, confirm/complete one step and move to the next. Save Progress. Refresh, close/reopen the tab and log out/in. Verify current step, completion, notes, issues, selected part and Guided/Engineering mode. The automated HTTP smoke separately verifies a real backend restart.
4. With your own configured provider key, consent to context and request a plan proposal. Check genuine provider metadata. Confirm no steps are saved until review/acceptance. Reopen a saved proposal from conversation history, edit a step and verify previous confirmation becomes Needs Review.
5. Open Camera; deny permission and retry deliberately. Test no-device behavior, start, source switching, capture, stop, retake and navigation cleanup. Confirm preview is local. Upload an image as fallback. Save it with storage consent and verify it returns on the same step. Attempt Next Step with an unsaved snapshot; it must require save/discard instead of relinking it silently.
6. Select saved photos, consent separately to cloud transmission and choose Check My Work. Inspect actual response/model/provider ID; test a missing key or quota/network failure. Failure must keep saved photos/progress and must not create a fake reply. Success must remain Needs Review / NOT VERIFIED, never automatic step completion.
7. Ask a photo question, simplify the current instruction and reopen earlier replies. Verify readable lists/headings/code/tables and escaped HTML. Use Load earlier conversations if the account has more than 50 saved messages.
8. Speak, repeat and stop an English instruction. Change voices where available. Change the current step during playback; speech must stop. Dictate a question where supported; confirm it fills the input without sending. Test denied microphone/service errors and the text fallback. Browser fixtures do not prove native audio.
9. In 3D editor, search/filter parts, add/select a part, use move/rotate gizmos, numeric fields, drag/drop and snap. Parent a camera to a controller; move/rotate the parent and verify descendants follow. Reparent without jumping. Hide/show the parent and confirm inherited visibility. Test undo/redo, removal cleanup, explode, annotations, reset/focus, save/reload and revision conflicts. Gizmos are disabled in exploded/live/simulation views.
10. Try leaving a dirty embedded editor; the app must warn and retain notes. Save assembly, then Save Progress. Saved design changes should reopen affected build confirmations for review.
11. Switch light/dark/system, Guided/Engineering and collapsed panels. Inspect no horizontal overflow, legibility, keyboard focus/labels, mobile navigation and serious/critical accessibility issues. Static token contrast measurements are supplied but are not a full WCAG audit.
12. Enroll a software device as SIMULATION and send a labeled packet; confirm stored values/history and simulation exclusion in the twin. Real calibrated hardware uses LIVE_REAL separately. Verify stale/revoked state and frozen recorded motion. Control intent must remain HOLD_NO_EXECUTOR.
13. Open Evidence and Settings export. Confirm saved snapshots, user-reported progress, private AI feedback, audit events and unresolved issues. Use a viewer account to confirm mutation controls/API are denied. Delete only disposable equipment/media; verify project-scoped access and expected evidence invalidation.

Keep real secrets out of screenshots and recordings. No GitHub/deployment/account changes are required for local acceptance.
